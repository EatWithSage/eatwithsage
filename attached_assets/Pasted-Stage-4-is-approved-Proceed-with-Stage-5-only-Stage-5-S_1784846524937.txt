## Stage 5 Scope

Complete final homepage QA and homepage-specific optimization:

1. Homepage SEO metadata
2. Responsive review
3. Accessibility review
4. Analytics verification
5. Performance review
6. Homepage functionality testing
7. Regression testing confirming non-homepage routes remain unchanged

Do not redesign sections or rewrite approved copy during Stage 5.

## 1. Homepage SEO Metadata

Review and confirm the homepage uses:

Title:

Sage | White-Labeled Retail Media Platform for Grocers

Meta description:

Sage helps grocers turn weekly food decisions into personalized, shoppable and monetizable digital experiences under their own brand.

Also review:

* Canonical URL
* Open Graph title
* Open Graph description
* Open Graph image
* Twitter/X card metadata
* Homepage robots directives
* Structured data already present on the homepage

Do not modify metadata on any non-homepage route.

If the current application architecture cannot reliably render route-specific social metadata, document the limitation rather than changing the entire site architecture.

## 2. Responsive Review

Review the full homepage at representative widths:

* 320px
* 375px
* 768px
* 1024px
* 1440px

Check every section for:

* Text overflow
* Horizontal scrolling
* Crowded or orphaned headlines
* Button wrapping
* Card alignment
* Uneven spacing
* Placeholder UI overflow
* Readability of the four hero benefit labels
* Mobile navigation CTA behavior
* Correct stacking order
* Excessive page length or repeated content
* Adequate spacing before and after the demo form

Make only corrective layout changes required for usability.

Do not change approved copy to solve layout issues unless absolutely necessary. If copy appears to require revision, report it instead of editing it.

## 3. Accessibility Review

Review the homepage for:

* One clear H1
* Logical heading hierarchy
* Keyboard-accessible buttons and navigation
* Visible focus states
* Valid anchor and scroll targets
* Color contrast
* Image alt text accuracy
* Decorative icon handling
* Semantic lists
* Form labels and error messaging
* Mobile navigation usability
* Reduced-motion behavior, if animations exist
* Duplicate IDs
* Missing landmark labels where materially useful

Run automated accessibility tooling if available.

Document:

* Tool used
* Issues found
* Issues corrected
* Issues deferred

Do not make sitewide accessibility changes unless required to prevent a homepage regression.

## 4. CTA and Functionality Verification

Verify:

* Header “Request a Demo” CTA appears only on the homepage.
* Mobile navigation “Request a Demo” CTA appears only on the homepage.
* Hero “Request a Demo” scrolls to `#demo`.
* Hero “See How It Works” scrolls to `#how-sage-works`.
* Homepage Final CTA scrolls forward to `#demo`.
* Demo form submits successfully or reaches the expected current submission behavior.
* All homepage navigation links work.
* No visible CTA points to a missing section.
* No placeholder button is accidentally interactive.
* No duplicate `id="demo"` or `id="how-sage-works"` exists.

Do not submit test data to a live CRM unless a safe test method is already available.

## 5. Analytics Verification

Identify the analytics currently used on the homepage.

Verify, without changing non-homepage behavior:

* Homepage pageview tracking
* Existing demo form tracking
* Existing CTA tracking, if present
* Whether the new header CTA is tracked
* Whether the hero primary CTA is tracked
* Whether the hero secondary CTA is tracked
* Whether the Homepage Final CTA is tracked

Do not invent a new event taxonomy during this stage.

If tracking is missing, document the recommended events and implementation locations. Only add tracking if it can reuse the existing analytics conventions without affecting other routes.
